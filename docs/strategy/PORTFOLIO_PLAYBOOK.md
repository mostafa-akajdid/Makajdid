# Portfolio Playbook

> This document defines the vision, philosophy, writing style and design principles of this portfolio.

Every decision made inside this project should follow this document.

If a future change conflicts with this playbook, the playbook wins.

---

# Mission

Create digital products that solve real problems through thoughtful engineering, clean user experiences and reliable software.

Software should help people.

Technology exists to solve problems.

---

# Vision

Build a portfolio that feels like a product.

Not a resume.

Not a template.

Not a collection of projects.

Visitors should understand who I am before they understand what I build.

---

# Positioning

Mostafa Akajdid

Full-Stack Developer

Building complete digital products from frontend interfaces to backend systems.

The portfolio should communicate balance.

Never present me as only a frontend developer.

Never present me as only a backend developer.

---

# Audience

Priority 1

Recruiters

Priority 2

Clients

Priority 3

Developers

Every page should answer their questions as quickly as possible.

---

# Personality

The portfolio should feel

- Calm
- Premium
- Human
- Honest
- Professional
- Modern
- Thoughtful

It should never feel

- Loud
- Flashy
- Salesy
- Corporate
- Generic
- AI-generated

---

# Voice

Write like a real engineer.

Not like a marketer.

Not like ChatGPT.

Sentences should be

- Short
- Clear
- Specific

Avoid buzzwords.

Avoid exaggeration.

Avoid empty claims.

---

# Principles

## Proof beats claims

Always prefer evidence.

Never rely on adjectives.

Bad

Fast.

Modern.

Scalable.

Good

Built with...

Reduced...

Handled...

Designed...

Measured...

---

## Simplicity wins

Simple language.

Simple design.

Simple navigation.

Simple interactions.

Complexity should exist only in the engineering.

---

## Consistency

Everything should feel like one product.

Typography.

Spacing.

Tone.

Motion.

Photography.

Writing.

Everything.

---

## Trust

Every section should increase trust.

If it doesn't increase trust...

Remove it.

---

# Visual Direction

Editorial.

Minimal.

Premium.

Timeless.

White space matters.

Motion should support understanding.

Never decorate for the sake of decoration.

---

# Content Rules

Every paragraph must do at least one thing.

- Explain
- Build trust
- Show proof
- Help navigation
- Help conversion

Otherwise remove it.

---

# We Never Say

Passionate developer

Pixel perfect

---

# We Always Show

Real work

Real experience

Professional communication

Continuous learning

---

# Definition of Done

A change is accepted only if it improves at least one of:

- Trust

- Clarity

- Premium feel

- Personality

- Performance

Otherwise reject the change.

# AI Instructions

Before changing anything:

Read this document completely.

Do not redesign sections without understanding the overall philosophy.

Prefer improving existing work over replacing it.

Do not introduce trendy UI patterns.

Do not invent fake metrics.

Do not invent projects.

Do not invent achievements.

Do not change the writing style.

When uncertain...

Ask.

Never assume.
